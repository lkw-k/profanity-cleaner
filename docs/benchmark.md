2026-08-19 측정. 봇이 404로 완전히 멈춰 있던 상태에서 정상 동작까지 복구하고, 마스킹 누출을 줄인 과정의 기록입니다.

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 봇 동작 | **전량 실패** (HTTP 404) | 정상 |

## 1. 봇이 멈춰 있던 원인

`llama-3.3-70b-versatile`이 Groq에서 퇴역했습니다. 모든 호출이 실패했습니다.

```
Error code: 404 - {'error': {'message': 'The model `llama-3.3-70b-versatile`
does not exist or you do not have access to it.', 'code': 'model_not_found'}}
```

인증(`401`)이 아니라 모델 조회(`404`) 실패였습니다. 계정에서 쓸 수 있는 모델 13개를 조회했더니 Llama 계열 중 생성용 모델은 남아있지 않았고(`llama-prompt-guard`는 분류 전용), `qwen/qwen3.6-27b`로 교체했습니다.

## 2. `reasoning_effort="none"`이 필수였던 이유

모델만 교체하면 이번엔 JSON 생성이 실패합니다. 남아있는 모델들은 추론 토큰을 먼저 소비하는데, 그 토큰이 `max_tokens`를 다 써버려 JSON이 완성되기 전에 잘립니다.

| 설정 | 결과 |
|---|---|
| 추론 켬(기본), `max_tokens=1000` | 5/5 실패 — `Failed to validate JSON` |
| **추론 끔, `max_tokens=200`** | **전량 성공, 출력 25~68토큰** |

`reasoning_effort`는 `none`과 `default` 두 값만 받습니다.

### `max_tokens`는 비용이 아니라 상한

과금은 실제 생성된 토큰 기준이라, `max_tokens`를 낮춰도 절약되는 토큰은 없고 긴 메시지가 잘릴 위험만 생깁니다. 실측한 하한은 다음과 같아 기존 200을 유지했습니다.

```
짧은 메시지   25~41토큰   → 40에서도 통과
긴 메시지     68토큰      → 60에서 잘림, 150에서 통과
```

## 3. 프롬프트 A/B

동일 모델(`qwen/qwen3.6-27b`), 동일 파라미터(`temperature=0.3`, `reasoning_effort="none"`, `max_tokens=200`)로 프롬프트만 바꿔 측정했습니다.

- 욕설 샘플 8종 + 정상 샘플 2종
- 프롬프트당 168회 호출 (4회차 합산)
- 누출 판정: `masked` 결과에 비속어 문자열이 남아있으면 누출

| | 구 프롬프트 | 신 프롬프트 |
|---|---|---|
| 비속어 누출 | 12/168 (7.1%) | **1/168 (0.6%)** |
| 정상 문장 오마스킹 | 0/48 | 0/48 |
| 평균 입력 토큰 | 143 | 165 |
| 평균 출력 토큰 | 30 | 28 |

누출은 **욕설이 여러 개 섞인 긴 문장에 몰렸습니다.** 구 프롬프트는 앞쪽 욕설만 처리하고 뒤쪽을 흘렸습니다.

```
입력:  아 좆같네 진짜 이게 뭐야 개빡치네 시발
구:    아 *** 진짜 이게 뭐야 *** 시발      ← "시발"이 그대로
신:    아 ***네 진짜 이게 뭐야 ***네 **
```

신 프롬프트에서 바뀐 핵심은 "비속어를 하나도 빠뜨리지 마라"는 명시와, 욕설이 여러 개 들어간 예시를 준 것입니다. 대가는 호출당 입력 토큰 +22입니다.

### 측정 편차 주의

회차별 구 프롬프트 누출은 1/48, 6/48, 4/48로 편차가 컸습니다. 표본이 작으면 "누출 0회"가 우연히 나옵니다. 위 수치는 4회차를 합산한 값입니다.

## 4. 동작 방식 변경

이전에는 원본 욕설이 채널에 그대로 남고 답글로만 마스킹 결과를 알렸습니다. 이제 원본 자체가 마스킹본으로 대체됩니다.

```
이전:  [작성자] 아 시발 진짜        ← 욕설 그대로 노출
       └ [봇] 원문: 아 ** 진짜 / 교정: 아 진짜

이후:  [작성자(웹훅)] 아 ** 진짜     ← 원본 삭제 후 재게시
       └ [봇] 아 진짜
```

Discord는 봇이 타인의 메시지를 수정할 수 없어, 웹훅으로 작성자 닉네임·아바타를 씌워 재게시하고 원본을 삭제하는 방식입니다. **재게시가 성공한 뒤에 삭제**합니다. 순서를 뒤집으면 API 실패 시 사용자 글이 영구 소실됩니다.

권한(`Manage Messages` / `Manage Webhooks`)이 없으면 이전 방식(답글만)으로 자동 폴백합니다.

## 측정하지 않은 것

- **`llama-3.3-70b-versatile` 대비 품질** — 모델이 퇴역해 재측정이 불가능합니다. 위 비교는 전부 `qwen3.6-27b` 기준입니다
- **KcBERT 탐지 정확도** — 이번 변경 대상이 아니며 그대로입니다. Groq은 KcBERT가 욕설로 판정한 메시지만 처리하므로, 탐지 자체의 누락은 위 수치에 포함되지 않습니다
- **`!train` 학습 파이프라인** — 미검증 (2026-09-03 점검 결과는 「남은 문제」 참고)

## 남은 문제

### 마스킹 별 개수 ±1 오차

마스킹 별 개수가 원문 글자 수와 어긋나는 경우가 있습니다. 누출은 아니라 기능상 문제는 아닙니다.

```
좆같네 → ***네   (좆같 2글자에 * 3개)
존나   → ***     (2글자에 * 3개)
```

### `!train` 학습 파이프라인 (2026-09-03 점검)

GPU가 있는 머신에서 학습을 돌리려고 코드를 점검한 결과입니다. 위 「측정하지 않은 것」의 "`!train` 미검증"을 구체화한 것입니다.

| 문제 | 근거 | 상태 |
|---|---|---|
| GPU를 쓰지 않음 | `src/`에 device 지정이 없어 모델·텐서가 `from_pretrained` 기본값인 CPU에 머묾 | **해결** |
| 학습 데이터 0건 | `feedback.db`의 `feedback` 테이블 0행 | 미해결 |
| 파일로 데이터를 넣을 수 없음 | `src/`에 파일을 읽는 코드가 없음. 투입 수단이 디스코드 🏴/🏳️ 반응뿐 | 미해결 |

**GPU 미사용** — 모델과 입력 텐서가 다른 device면 PyTorch가 `Expected all tensors to be on the same device`로 죽으므로, 모델(`model.to`)·입력(`inputs.to`)·레이블(`torch.tensor(..., device=)`)을 함께 옮겨야 합니다. `cuda.is_available()`로 판정하므로 GPU가 없는 배포 서버에서는 그대로 CPU로 떨어집니다.

**학습 데이터 0건** — `feedback.db`는 `.gitignore`에 있어 저장소에 올라가지 않습니다. 다른 머신에서 clone하면 빈 DB가 새로 생기므로, 학습 데이터는 따로 옮기거나 그 머신에서 다시 모아야 합니다. 학습된 가중치(`models/trained/model.safetensors`)도 `*.safetensors` 규칙에 걸려 마찬가지입니다.

**배치 분할 없음** — `_run_epoch`은 전체 데이터를 한 번에 forward합니다. `EPOCHS=3`은 사실상 3 step이고, 피드백 수십 건 규모에서는 문제없지만 파일로 수천 건을 넣으면 OOM이 납니다. 파일 입력 경로를 만들 때 같이 손봐야 합니다.

### 스펙과 구현의 차이

`.claude/skills/planning/spec.md`의 최초 설계와 현재 구현이 갈라져 있습니다. 일부는 의도한 개선이고, 일부는 미구현입니다.

| 스펙 | 현재 구현 | 판단 |
|---|---|---|
| 한국어 + 영어 (`unitary/toxic-bert` 병행) | 한국어만 | **미구현** |
| 두 모델 OR 조합, confidence > 0.7 | KcBERT 단독 `argmax` (임계값 0.5에 해당) | **미구현** — 임계값을 조절할 수 없음 |
| wordlist(`data/wordlist_*.txt`) 기반 마스킹 | Groq LLM 마스킹 | 의도한 변경 (문맥 대응·오타 변형에 강함) |
| `src/detector.py`의 `ProfanityDetector` 클래스 | `src/bot.py`에 함수로 인라인 | 규모상 문제없음 |
| 경고 메시지(임베드) 전송 | 교정문 답글만 | 의도한 변경 |
| Phase 1 (KCBERT 파인튜닝) 체크박스 미완 | 실제로는 완료 (eval f1 0.918, 허브 업로드) | 스펙 문서가 뒤처짐 |
| Phase 4 통합 테스트 | 자동화된 것은 `database` 단위 테스트뿐 | 미수행 |
